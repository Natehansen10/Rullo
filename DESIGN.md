# Weem Watts Design Rules

Numbers first, a warm light page, and every color has one job. Built to be read from the saddle, a few feet from the screen.

Source: [Weem Watts Design System](https://claude.ai/artifact/MwUnE5KEPgbmD8FAaiLfcs). In code, `src/styles/tokens.css` is the single source of truth. No hex color may appear anywhere else.

## Principles

- **One big number.** Live power is the hero. Everything else supports it.
- **Color means something.** Chrome is neutral warm gray. Color appears only for an action, a channel, or a state.
- **Cobalt is rare.** `accent` has three jobs: the primary action (one per screen: Connect, then Start ride / Start workout in the same slot once connected, except on the Workout page, where the step button is primary, in the workout builder, where Save is primary, and on Home, where the next-step button is primary; the top bar's buttons are secondary on all three), live power, and route progress (the ridden stretch and position dot on the elevation profile). It never fills anything bigger than a button.
- **Calm while riding.** Numbers update in place. Nothing jumps, bounces, or flashes.
- **Heart rate is a number, not a channel.** It has its own tile in `fg`, with no zones, no zone color and no target. A stale or lost sensor turns the tile `fg-subtle` and changes nothing else: the StatusPill, the ride and the trainer are about the trainer only.
- **Never show frozen numbers as live.** Stale data turns `fg-subtle` and the StatusPill says "Reconnecting". An auto-paused ride does the same with "Paused" (`idle` tone), and the control row status reads "Paused. Pedal to resume."
- **Say when nothing is being saved.** Nothing is recorded until the rider presses Start. Connected and waiting, the screen says so in three calm places and nothing flashes: the StatusPill reads "Not recording" (`warn`), the Time tile's label row reads "Not recording" (`ww-label` in `state-under`), and the control row's second line reads "Press Start ride." (or "Press Start workout."). Time and Distance sit at 0:00 and 0.00 in `fg-subtle`. Power, cadence and speed are live.
- **Say who sets the load.** The control row's first line is always one of "Workout sets the load.", "Hills set the load.", "You set the load.", "You set the load for now." (a workout is loaded and not started) or "Workout is done." It follows what the trainer is doing, so it changes when the rider switches mode by hand.
- **Units are lb and miles.** Never show kg or km.

### Power zones

For workout blocks and zone codes (v3.2). Each meets 3:1 on `surface`. Z2 is gray-blue, not blue, so it never reads as the accent. Always pair a zone color with its code (Z1 to Z7). The boundaries live in one list, `ZONES` in `src/lib/workout.ts` (tops at 55, 75, 90, 105, 120 and 150% FTP). The workout strip, the builder graph and `ZoneTable` are all built from it. A block is drawn in the zone of the whole watts it comes to at the rider's FTP, so a block's color and the chart's watt ranges always agree.

## Type

- **Archivo** (variable, with the width axis) for everything. JetBrains Mono for small technical text only (smoothing toggle, footer).
- Installed through `@fontsource-variable`. No CDN.
- **Live numbers:** weight 600, `font-stretch: 112%`, `tabular-nums`, line-height 0.9 (`.ww-num`).
  - Power: 144px in `accent` (96px under 1200px wide).
  - Other tiles: 56 to 64px in `fg`.
  - Control values (resistance level): 40px in `fg` (`.ww-num-control`).
  - Course stats (grade, elevation, climbed, to go): 28px in `fg` (`.ww-num-sm`).
  - Units: 40% of the number size, `fg-muted`, 4px after the number (`.ww-unit`).
- **Labels:** 12px, weight 500, uppercase, letter-spacing 0.06em, `fg-muted` (`.ww-label`).
- Never Inter or Geist.

## Spacing and shape

- Spacing steps only: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 (Tailwind `1 2 3 4 6 8 12 16`). Other steps are removed from the theme.
- Radius: 4 for chips and pills (`rounded-sm`), 6 for buttons (`rounded-md`), 10 for panels (`rounded-lg`). Fully round only for status dots.
- Depth comes from surface steps (white `surface` panels on the `bg` page, `raised` for controls) and 1px hairlines. No shadows.

## Motion

- 120ms for hover and press. Press scales to 0.98 (`.ww-press`).
- 200ms for state changes (stale gray-out, status dot).
- Ease-out `cubic-bezier(0.2, 0, 0, 1)`. No bounce or overshoot.
- `prefers-reduced-motion` sets every duration to 0 and turns off the press scale.
- A hover overlay (the workout strip's details) fades in over 120ms and is positioned over the page, so showing it moves and resizes nothing.
- Live power updates in place. No digit rolling.

## Layout

- **Top bar:** "Weem Watts" wordmark (a link to Home) and the page tabs (Home, Ride, Workout, Profile) left. StatusPill and the ride button right, on every page. The rightmost slot is the ride's next step: Connect (primary), then Start ride or Start workout (primary, with a secondary Disconnect to its left), then End Ride (secondary, two clicks), then Download FIT and New ride. Start has no row of its own, so it costs no height in any ride type and both labels are in one place. Connect or Start from another page jumps to Ride. A click on End Ride in the first second after Start is ignored, so a double click on Start cannot arm it. A click on New ride in the first second after Confirm end is ignored the same way.
- **Home page (`#/`, where the app opens):** laid out after Zwift's home screen and drawn with this system's tokens: a left rail and a main column (`.ww-home`: the rail is `--ww-home-rail`, 384px; under 1200px the rail goes on top with its two panels side by side, so the history rows keep the full width; one column under 900px), capped at `max-w-7xl`, left-aligned under an `h1` "Home". Every block is its own `surface` panel with a body-size, weight 600 heading; no panel sits inside another. The rail: **Rider** (`Stat` for FTP in W and weight in lb, one `fg-muted` line "Set on the Profile tab.") and **Power zones** (`ZoneTable`). The main column, top to bottom: **Next** (one `fg-muted` sentence and the page's one primary button, "Set up a ride" or "Go to Ride"); **Totals** (two rows split by a hairline, "All rides" and "Last 7 days", each a wrapping row of `Stat`: Rides, Time, Distance in mi, Climbed in ft, Best 20 min in W; shown only when there is a ride; "--" in `fg-subtle` while rides are still being read, so nothing moves when the numbers land); **Ride history** (heading, one line of help, then the ride history table). With no rides the history panel is its heading and one plain line, and there is no Totals panel. Nothing on Home changes a ride in progress; the only thing it can change is deleting a finished ride. On Home every top bar button is secondary (Connect, Start, Reconnect, Download FIT), so the page keeps one primary.
- **Ride page (`#/ride`):** live data only: the ride panel, plus notices (recovery, errors). No pickers.
- **Workout page (`#/workout`):** two steps, one at a time, under a mono "Step n of 2", the step title and one line of help. What is picked here is staged: it reaches the Ride tab only through Ride this workout or Done. The setup line says so in plain words. Its first row is the `ww-label` "Picked", the setup name and a mono detail; under it, in `fg-muted`, either "This is on the Ride tab now." or "Not on the Ride tab yet. The Ride tab has Flat road · Free ride." (naming what the Ride tab has). The setup can be changed until Start is pressed, with the trainer connected or not. Locked from Start until New ride (the ride's own setup line only, labeled Riding or Last ride).
  - **Step 1, the course:** a grid of cards on the page, the same card as step 2 (2 columns, 3 from 1280px, 4 from 1536px): Flat road first (a `line-strong` baseline where the profile would be), then one card per course with a small elevation profile (48px, `raised` fill, `fg-subtle` line), the name, and a mono line with miles, feet of climbing and source. The card picked on this tab is `raised` with an `fg` border (picked, not yet on the Ride tab). Under the grid, the selected course's overview in one panel: name, `CourseOverview`, and the start mile. Then the setup line in its own panel with Next (primary).
  - **Step 2, the workout library** (laid out after Zwift's Workouts page): a side menu on the left (All workouts, Custom, each with a mono count; the current one is a `surface` chip with a `line-strong` border, as in TabNav), then the filter row (Length and Difficulty, both SegmentedControl, and a mono count) over a grid of cards (2 columns, 3 from 1280px, 4 from 1536px). Cards sit straight on the page (`bg`), never inside a panel. The first card is always the Custom Workout tile (`raised`, `line-strong` border, a plus, the name at title size); then Free ride; then one card per workout: a small `WorkoutStrip` without labels (48px), the name, and a mono line with length, difficulty and source. The card of the picked workout (or Free ride) is `raised` with an `fg` border. Clicking a workout card opens its **overview** in place of the grid; looking does not pick it. Ride this workout picks it, puts the course and that workout on the Ride tab and goes there. The Free ride card picks "no workout" and stays on the page. The overview's mono line adds "on the Ride tab now" for the workout the Ride tab has: one panel with ← All workouts and the name, `Stat inline` for duration and intervals, the buttons (Edit for a custom workout, Edit a copy, Delete with a `danger` confirm for the rider's own, and the primary Ride this workout), the description, and the strip at `ww-builder-graph` height. Under both, the setup line in its own panel with Back, and "Done: go to Ride" (primary) when no overview is open, so there is one primary per screen. Done puts exactly the setup line beside it on the Ride tab. No import buttons here.
- **Workout builder (`#/workout/build`):** a side trip from the Workout tab (the Workout tab stays current in the top bar). One panel, laid out after Zwift's workout editor and drawn with this system's tokens. Top to bottom, split by hairlines: a header row (← Back, the workout's name as the title in `ww-title-field`, a mono note); the details (Description left, the Difficulty tag right); the block area (`BuilderGraph`: the selected block's fields in a bordered `surface` box right above it, the graph, the block palette on the right, then Undo, Delete block and the key hint); the bottom bar (Display: % FTP / Watts, `Stat inline` for workout duration and intervals, a mono line, and the Step list toggle); the optional step list (`StepRow`, `RepeatGroup`, the add row); and a footer row with status text left and Save (primary) right. Back turns into `danger` "Discard changes" on the first click when there is unsaved work. The page may scroll. Locked mid-ride (one line in a panel).
- **Profile page (`#/profile`):** the rider panel (its last block is Power zones: `ZoneTable` right under the FTP row, so it follows the FTP as it changes), then "Your files": one panel with a Courses block and a Workouts block, each a heading, one line of help and its buttons (Import GPX; New workout and Import ZWO), followed by the rider's own files as rows: a custom workout has Edit and Remove (Remove asks twice, `danger` "Confirm remove"), an imported workout has Edit a copy and Remove, an imported course has Remove.
- **One ride panel:** hero power tile on the left (two fifths of the width at 1280px and up), five tiles on the right in two rows, split by `line` hairlines: Cadence, Heart rate and Speed on top (9 : 8 : 8, Cadence a little wider for its cue), Distance and Time below at half width each (they hold the long values, 112.34 mi and 1:23:45). The Heart rate tile is always there, so the layout never changes: "--" with a Connect control in its label row when there is no sensor. On a course, a full-width elevation profile row comes next; with a workout, a workout row. With both, both rows show in compact form: labels sit beside their numbers on one line (`Stat inline`), the profile is 48px and the strip 56px, and the workout name truncates before anything wraps. A full-width control row sits along the bottom. All rows are in the same panel, split by hairlines. When the workout's current interval has a cadence target, the Cadence tile's label row shows it in mono ("target 90"; the tile's unit is rpm): `fg-muted` before the workout starts, then `state-on`, `state-under` or `state-over` within or outside 5 rpm, always with the word (on, under, over) so color is never the only signal. It is a cue; the trainer never gets it. On a course, the right end of the course row's stats line says what the course is setting, in `fg-muted`: "The course sets speed, not the load." or, in Grade, "The course sets speed and the load." Before the workout starts, the right end of the workout row reads "Connect to start" or "Press Start workout" (not in compact form); the button itself is in the top bar.
- **Fit a laptop:** at 1280x720 the control row and its key hint must stay on screen in every ride type. With a course or workout row the tiles and control row use 16px vertical padding (24px on a free ride). The control row status is always two lines, one line each, so nothing moves when the words change: who sets the load (`fg`), then the detail (`fg-muted`): "Press Start ride.", "Paused. Pedal to resume.", "Released until 60 rpm.", "Easing in to target", "Intensity, every target", "Hill feel · trainer 3.2%", "Workout targets are off.", "Refused. Retrying." At 1280 on a course the status has about 180px: keep every line under 160px (about 24 characters) so the key hint stays on one line. The key hint is the same in every mode ("↑↓ 1 · +/− 5 · shift ↑↓ 10 · E mode"); the unit is on the value beside it.
- Left-aligned. No centered hero layouts.

## Components (`src/components`)

| Component | Use |
| --- | --- |
| `MetricTile` | One live number with label and unit. `size="hero"` for power only. `dim` grays it out. `action` puts a small control or note in the label row (the smoothing toggle, the cadence cue, "Not recording" on the Time tile while waiting for Start, the Heart rate tile's connect control). |
| Tile link (`.ww-tile-link`) | A text control in a tile's label row, for the Heart rate tile only: label type (12px, uppercase) in `fg`, underlined, `fg-muted` on hover, so the row keeps its 16px line and the panel its height. One button for every sensor state: Connect, Connecting (plain `fg-muted`, not pressable), Disconnect, Reconnecting (`state-under`; pressing it stops the retries), Retry. It is never a `Button`: a button would make the tile taller than 1280x720 allows. 8px of padding on each side widens the click target without moving anything. |
| `StatusPill` | Connection and ride state. Tones: `on` (Connected: a ride is on and recording), `warn` (Connecting, Reconnecting, Not recording: connected and waiting for Start), `error` (Disconnected, Not supported), `idle` (Not connected, Paused, Ride ended). |
| `Button` | `primary` (Cobalt, one per screen), `secondary`, `danger` (the second click of a two-click confirm: End Ride, Discard changes, Confirm remove, Confirm delete; hover goes to `surface` so the red text keeps 4.5:1). `size="sm"` (8px by 4px padding) only for dense rows: the builder's step rows and the ride history rows. |
| `SegmentedControl` | Small option sets, like the 1s / 3s / 10s smoothing toggle. Selected option is a `surface` chip with a `line-strong` border; hover only darkens text. One Tab stop, Left / Right arrows move the selection. |
| `ElevationProfile` | Course stats row plus an SVG profile (`compact`: stats on one line, profile at `ww-profile-compact`): `raised` fill, `fg-subtle` line, `accent` for the stretch ridden and the position dot. | `TabNav` | Page tabs in the top bar (Home, Ride, Workout, Profile): links on a `raised` track; the current page is a `surface` chip with a `line-strong` border (same look as SegmentedControl, body size). |
| `WorkoutPage` | Its own screen at `#/workout`: the two-step setup (CoursePicker, then WorkoutPicker) with the setup line and step buttons. The picks are staged; the setup line says whether the Ride tab has them. Open until Start is pressed. While locked (Start to New ride), the ride's setup line only. |
| `ProfilePage` | Its own screen at `#/profile`. Rider panel: rows split by hairlines, label and help text left, input right. "Your files" panel: Import GPX; New workout and Import ZWO; the rider's files as rows with their buttons (Edit or Edit a copy, Remove). Locked mid-ride. |
| `TextField` | A typed field at body size: `raised`, `line-strong` border, `radius-md` (`.ww-field`). Optional `ww-label` above it. Takes text so "12:00", "90%" and "225w" can be typed; a bad value turns the border `state-over` once the field is left, and the reason is always written out in the builder's status line. |
| `WorkoutBuilder` | Its own screen at `#/workout/build` (see Layout). Every change is kept as a draft in the browser and can be undone. |
| `BuilderGraph` | The builder's block canvas at `ww-builder-graph` height (264px): a `raised` plot with `line-strong` zone lines, Z1 to Z6 codes and time ticks in mono `fg-muted`; each block's width is time, height is % FTP and fill is its zone token, ramps sloped, `surface` hairlines between blocks. The selected block has a 2px `fg` outline; the same outline is its focus ring. A drop position is a 2px `fg` line. Cobalt is never used here. A cadence target shows as a mono note on a `surface` chip at the foot of the block. Beside the graph, the palette: small `raised` buttons, each a 28 by 16 swatch (zone color, slope or bars) and its name (Z1 to Z6, Warm up, Cool down, Intervals, Cadence). Click adds after the selected block; drag drops at a spot. Drag a block's top edge for power, right edge for time, body to move or onto Delete block. Keys on a block: ← → select, ↑ ↓ power, Shift + ← → time, Alt + ← → move, Delete, Ctrl + D, Ctrl + Z. |
| `StepRow` | One step in the builder's step list (the typed view of the same blocks, behind the Step list toggle), one line on the shared grid (`.ww-step-row`): mono step number, Steady / Ramp `SegmentedControl`, time, target (two fields and an arrow for a ramp) followed by a mono echo of what it comes to at the rider's FTP (zone code and the other unit), cadence, label, then small buttons: ↑, ↓, Copy, Delete. Alt + ↑ / ↓ moves the row, Ctrl + D duplicates it; focus stays with the row. |
| `RepeatGroup` | A repeat in the builder: a header row (number, "Repeat", a count field, "times", a mono summary, the same row buttons), then its steps numbered 2.1, 2.2 and set in from a `line-strong` rule, then small Add step to repeat / Add ramp to repeat buttons. Indentation and the rule group it; never a nested panel. |
| `CoursePicker` | Step 1: Flat road or a course, as cards (`role="radio"`) with a small elevation profile. The selected course opens `CourseOverview` and the start-mile input in a panel under the grid. |
| `CourseOverview` | The route at a glance: distance, climbing, low and high (`Stat inline`) over an elevation profile at `ww-profile` height (`raised` fill, `fg-subtle` line). A Cobalt hairline marks a start mile above 0. |
| `WorkoutPicker` | Step 2: the workout library (side menu, filters, card grid led by the Custom Workout tile) and the selected workout's overview. See Layout. Cards are `role="radio"`; the picked workout stays listed whatever the filters say. |
| `WorkoutStrip` | Every interval as a block: width is duration, height is % FTP, fill is the zone token (`z1` to `z7`), ramps sloped, `surface` hairlines between blocks. `labels={false}` drops the watt labels (the small graph on a workout card). Each block is labeled with its watts after intensity (ramps as start→end) in mono `fg-muted` above it, when the block is wide enough. The part done is washed with `surface` at 60%; a Cobalt line marks the position. **Hover details** (`ww-strip-tip`; on wherever the watt labels are, so not on the card graphs): pointing at a block outlines it with a 1px `fg` line and shows one mono line on a `surface` chip with a 1px `line-strong` border and radius 4: the label if it has one, the zone (an 8px swatch with its code), watts after intensity, % FTP of those watts (ramps as start→end), length (m:ss or h:mm:ss) and the cadence target in rpm if it has one. Values in `fg`, units in `fg-muted`. The chip is an overlay, 22px tall (12px line, 4px padding, 1px border): absolutely positioned 4px below the strip on the Ride page, so it ends 26px under the strip, and above it in the workout overview, centered on the block, kept inside the strip's width at the first and last block, flipped to the other side when it would leave the window. On the Ride page it must cover no number and no button: keep at least 28px between the strip and the control row's step buttons (today 12px of row padding, the 1px hairline and 16px of control row padding, 29px; 33px with the workout row alone). It never takes space, never takes a click (`pointer-events: none`) and fades in over 120ms (0 with reduced motion). Mouse and pen only; the blocks are not tab stops. |
| `WorkoutRow` | Ride panel row for a workout, one line at desktop width (the name truncates first): name, interval (label, n of N), target (W and %), a cadence target in rpm when any interval of the workout has one ("--" on intervals without; labeled RPM in `compact`), interval left, next target (or best minute in a ramp test), workout left, then the strip at `ww-profile` height (`compact`: one line, shorter labels, strip at `ww-strip-compact`). Before it starts: plain text, "Connect to start" then "Press Start workout" (the primary button is in the top bar, so there is one primary on screen). After: Skip interval / End test. A secondary `Start workout` button shows here only for an old unfinished ride that was resumed with its workout never started. No buttons once the ride has ended. |
| `ZoneTable` | The rider's power zones as a plain table (`.ww-zone-table`), one row per zone, Z1 to Z7, rows split by `line` hairlines: a 12px swatch in the zone token with its code in mono `fg` (color is never alone), the name in `fg`, the % FTP range in mono `fg-muted`, and the watt range at the rider's FTP, right-aligned, weight 600, `tabular-nums`. Watts are whole numbers; each zone starts one watt above the last, and Z7 is open-ended ("375 W and up"). Header cells are `ww-label`. It has no panel of its own: on the Profile tab it is a block in the rider panel right under the FTP row, with a heading and one line of help; on Home it has its own panel in the rail. |
| `HomePage` | Its own screen at `#/` (see Layout). Reads saved rides; the one thing it changes is deleting a finished ride. |
| Ride history table | Part of `HomePage`, the rows of its Ride history panel: a plain table (`.ww-table .ww-history`) that spans its panel, header cells in `ww-label`, rows split by `line` hairlines, newest first. | `Stepper` | At 1280px and wider the row never wraps: the status text takes the space left (two lines at most inside the row's height) and the key hint stays on one line. Resistance (%), ERG target (W) and workout intensity (%) all use the same 1 / 5 / 10 steps and keys (arrows 1, + / - 5, Shift + arrows 10). Inputs use `raised` with a `line-strong` border and `radius-md` (`.ww-field` for text fields). Build new UI from these. Add a component here before using a new pattern.

## Banned

Purple, gradients, blur, glow, shadows, emoji, nested panels, centered hero layouts, Inter, Geist, default shadcn or Tailwind palette colors, hex values outside `tokens.css`.
